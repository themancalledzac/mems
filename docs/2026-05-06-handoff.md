# Memory Palace — Handoff Snapshot (2026-05-06)

> Status of the repo as of today. Honest accounting of what works, what keeps breaking, and where this codebase has accumulated more surface than the underlying problem requires. Written for the next agent (or future self) so they can pick up cold.

---

## 1. Scope of this repo (what it actually is)

A Python package that:

- **Wraps the upstream `mempalace` PyPI library** (v3.3.0) into a long-running FastMCP server on `localhost:8787`.
- **Indexes multi-repo content** under `~/Code/*` into per-repo "wings" with a Wing → Hall → Room → Drawer taxonomy + cross-wing tunnels.
- **Maintains a User Wing** (`wing_user`) for persistent personal context across agent sessions.
- **Ships IDE integration** for Cursor (`.mdc` rules + `mcp.json`), Codex (`config.toml` append), and Claude Code (`settings.json` MCP entry + hooks + `~/.claude/CLAUDE.md` protocol).
- **Provides a `mems` CLI** for sync, search, publishing, repo registry ops, and a Jira/hybrid query mode.

**Trajectory.** First commit on this branch was 2026-04-15 (project scaffolding). 47 commits later it covers everything in the 426-line `CONTEXT.md`. The vision grew faster than the validation. See §4.

## 3. Recurring failure modes (the painful pattern)

These are issues that have **failed multiple times despite multiple fix attempts**. Catalogue them so the next round doesn't repeat the same procedural-only fix.

### 3a. Subagent dispatch without Memory Palace orientation

**Three documented occurrences in 9 days.** Each transcript: N reads + M bash filesystem calls + 0 `mempalace_*` calls.

| Date | Memory ID | Prior fix in place |
|------|-----------|--------------------|
| 2026-04-28 | `user-d51dbc54` | None (this prompted creating `~/.claude/snippets/mempalace-orientation.md`) |
| 2026-04-29 | `user-2fb9634b` | Snippet existed; CLAUDE.md said "prepend it." Still skipped. |
| 2026-05-06 (today) | `user-bb7e5553` (this fix) | Snippet + CLAUDE.md hard rule + audit doc + prior memory. Still skipped. |

**Quote from the 2026-04-29 memory** (verbatim): *"Procedural memory alone is brittle for this class of problem."*

**Today's fix.** PreToolUse hook on the `Agent` tool that lints the subagent prompt and **blocks** the dispatch if the orientation marker is missing. See [`docs/superpowers/2026-05-06-subagent-orientation-enforcement.md`](superpowers/2026-05-06-subagent-orientation-enforcement.md). **Installed in `~/.claude/settings.json` with backup `settings.json.bak.20260506T234627Z`.** Effective on next Claude Code reload.

**Limit of the fix.** Only gates outbound `Agent` calls. Does **not** gate the parent's own `Read`/`Glob`/`Grep` discipline. The parent loop remains procedural.

### 3b. Parent agent skipping mempalace under task pressure

The parent ALSO violates the per-batch rule. Documented in `user-3c4c2b0` (2026-04-28) and exhibited again today at the start of this session (7 reads + 12 bashes before any `mempalace_search`).

**Why no fix shipped today.** A PreToolUse hook on `Read`/`Glob`/`Grep` checking that mempalace was called recently has **high doom-loop risk** — see `feedback_mempalace_hook_doom_loop`. The parent has CLAUDE.md visible at all times; the loop stays procedural until a non-doom-loop design surfaces.

### 3c. Protocol relapse within hours

`user-43d008dd` (2026-04-29): *"Memory Palace Protocol relapsed within hours of the orientation snippet fix being put in place."* Even with the snippet, the audit doc, the CLAUDE.md hard rules, and the explicit precedence rule (user CLAUDE.md > superpowers > system prompt), the parent reverted to procedural-only behavior under task pressure.

The pattern is generalizable: **any "agent forgot to do X procedurally" failure that survives ≥2 fix attempts is a candidate for hook-level enforcement**, not another stronger rule.

### 3d. README / taxonomy drift

`user-c2aa655e` (2026-04-18): *"README taxonomy descriptions drift fast — small mismatches ('wings → rooms' when the real shape is 'wings → halls → rooms') compound into reader distrust."*

The taxonomy was just rewritten across `config/mempalace.yaml` (commit 5b6c127), with `wing_user` added (def84ac), and a sync-engine fix to support the new shape (2de2a60). The README, CONTEXT.md, and the `.mdc` rules need to be re-scanned for stale references — they were written when the taxonomy was flatter.

### 3e. Plugin skill files are uneditable

`user-908575b` (2026-04-18): the `superpowers` and `feature-dev` plugins' skill files live under `plugins/cache/` and are **auto-managed**. Edits get overwritten on update. Only CLAUDE.md is a durable surface for protocol changes. Anything that needs to change skill behavior has to be expressed as a CLAUDE.md override, not a skill edit. This caps how much enforcement the protocol layer can carry.

### 3f. `feature-dev:*` subagents can't use mempalace at all

Structural plugin limitation: `feature-dev:code-explorer` / `feature-dev:code-architect` ship with a restricted Tools allowlist that does not include `mcp__mempalace__*`. Even with orientation, they cannot call the tools. Workaround documented in CLAUDE.md: prefer `Explore` or `general-purpose` for code exploration. The orientation hook (§3a) deliberately skips `feature-dev:*` to avoid pointless friction.

## 4. Bloat assessment

The repo grew faster than its purpose required. Some of the surface earns its place; some looks like premature scaffolding for a vision that may not need every layer. Cataloguing so a cleanup pass can be intentional.

### 4a. Surface area, by directory

```
src/         12 files   FastMCP server, sync, wing_user, wingpack, snapshot/restore
mems_cli/    12 files   CLI dispatcher + 6 command modules + helpers
integration/  6 files   .mdc x2, .toml, .json, .sh, claude_code/ (hook)
scripts/      5 files   setup.sh + 3 IDE installers + cursor_rules/
tests/       16 files
docs/         3 dirs    superpowers/{plans,specs,protocol-audit}, TROUBLESHOOTING.md
config/       2 files   mempalace.yaml, repos.json
```

**Compare to the original mempalace package**: a single PyPI library with miner + searcher. This repo is ~20x the surface area for "wrap it and add multi-repo + recovery + IDE integration."

### 4b. Conceptually-suspicious surface

| Component | Earns its place? | Why questionable |
|-----------|------------------|------------------|
| `mems_cli/commands/tickets.py` | ❓ | Stdlib Jira v3 client. ~200 lines. Has nothing to do with memory palace; it's "things I want my CLI to do." Could live in a separate `jira-cli` repo. |
| `mems_cli/commands/hybrid.py` | ❓ | A 30-line join of `tickets` + `mempalace_search_all`. If `tickets` leaves, this leaves with it. |
| `src/auto_publish.py` (post-sync wingpack publish) | ❓ | Wingpacks are a cold-start optimization. The publish-back-into-source-repo flow + compat gates + 3-mode aliasing (ask/overwrite/skip ↔ default/force/keep) is a lot of code for "skip re-embedding on a fresh palace." How often does palace start fresh? |
| `src/wing_user_snapshot.py` + `restore_wing_user.py` | ⚠️ | Daily backup with retention pruning + boot-time auto-restore is real protection if `palace/` gets wiped. But the restore path has only ever been exercised in tests. The real value depends on how often the volume gets nuked. |
| Cursor `.mdc` rules (`integration/user-wing.mdc`, `mempalace-discovery.mdc`) | ❌ for Claude Code | `.mdc` files are NOT read by Claude Code (`user-7c5e7d1c`). Maintaining them in parallel with `~/.claude/CLAUDE.md` doubles maintenance and invites drift. They earn their place ONLY for actual Cursor users. |
| 3 separate IDE installers (`scripts/install_{cursor,codex,claude_code}.sh`) | ⚠️ | Reasonable now, but they re-implement the same "merge config, idempotent, backup" logic in three flavors (jq + bash, bash + grep, bash + python heredoc). One python module + three thin shell shims would be cleaner. |
| `setup.sh` orchestrator | ⚠️ | Calls into the three IDE installers. With three flavors of merge logic, `setup.sh` is more "switch between approaches" than "compose primitives." |
| `wing_user` `work` hall (the 7th hall, beyond the canonical 6) | ❓ | Added late (`user-05814afd`). Captures "operational state" (current_ticket, todo, wip). May overlap with `goals` and `decisions`. Worth checking if it's actually being written to vs the standard 6. |
| Wingpack format (manifest + keywords + rooms + prompts JSONs in a zip) | ⚠️ | 4 sidecar files per wing. The `prompts.json` file in particular — what reads it? Audit before keeping. |

## 7. Recommendations for the next agent

1. **Don't add another layer when a layer is already failing.** The orientation snippet, then the CLAUDE.md hard rule, then the audit doc, then a memory entry, then a stop-hook, then a PreToolUse hook — each was added because the previous one was insufficient. If a 4th layer needs to land, that's signal the design is wrong, not that the rule needs to be louder.

2. **Verify the hook before assuming protection.** It's installed and tested but has only run end-to-end against synthetic JSON payloads. The real test is the next code-task subagent dispatch. Watch for: (a) does it actually block? (b) is the block message visible to the parent agent? (c) does the parent then prepend orientation and retry?

3. **Resist scope.** The repo absorbed Jira integration, wingpack publishing, multi-IDE installers, disaster recovery, and a 7th hall in 3 weeks. Each addition was reasonable in isolation. The composite is 20x the surface of the underlying mempalace library. Before adding, ask: does this earn its place against the cleanup candidates in §5?

4. **Pick one source of truth per concept.** The taxonomy lives in `config/mempalace.yaml`. The README, CONTEXT.md, `.mdc` files, and CLAUDE.md all describe it from memory. They drift. Generate downstream docs from the YAML, or stop mentioning the shape outside it.

5. **The protocol is the product, not the scaffolding.** A user with a working `mempalace_search` and consistent agent adherence is the win. Snapshots, wingpacks, multi-IDE installers, Jira hybrids, and a 12-module CLI are scaffolding around that win. If something in the scaffolding fails, fix it; if it isn't being used, delete it.
