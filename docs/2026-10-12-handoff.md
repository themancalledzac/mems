### 2. Remove `sentence-transformers`

**Finding.**
- `pyproject.toml:16` lists `sentence-transformers>=2.7.0`. No code imports it in `src`, `mems_cli`, `scripts` or `integration`.
- mempalace 3.6.0 doesn't depend on it: it requires chromadb, huggingface-hub, numpy, python-dateutil, pyyaml and tokenizers.
- Embedding uses chroma's ONNX MiniLM, which MR-0 bakes into the image.

**Evidence.** In `memory-mempalace`, the `pip install .` layer is 6.38 GB of the 10.5 GB image. The biggest pieces in site-packages:
- `nvidia`: 3,341 MB;
- `torch`: 959 MB;
- `triton`: 817 MB;
- `transformers`: 116 MB.

All of them come in through `sentence-transformers`.

**Change.**
- Remove the dependency from `pyproject.toml`.
- Fix the `README.md:37` line that lists it.
- Rebuild the image.

**Proof.**
- The image shrinks by about 5 GB.
- `docker run --rm --network none <image> python -c "from chromadb.utils.embedding_functions import DefaultEmbeddingFunction as D; print(len(D()(['x'])[0]))"` prints 384.
- The server starts healthy, and search returns the same top hits as before for a few saved queries.

**Risk.** The embedding model must not change. Chroma's default and the old sentence-transformers model are both `all-MiniLM-L6-v2`, and the palace's stored vectors are what the server already uses. The startup warning `EmbedderIdentityUnknownWarning` says no embedder identity is recorded. Consider running `mempalace palace set-embedder --model all-minilm-l6-v2` once, with the server stopped.

### 3. Local venv mismatch (spec item A4)

**Finding.** `.venv` imports mempalace 3.3.6 from an editable install of `~/Code/mempalace`. `pyproject.toml` pins `mempalace==3.6.0`, and the container runs 3.6.0.

**Effects.**
- `test_indexable_config_exclude_patterns` is skipped locally, because `GitignoreMatcher.from_patterns` doesn't exist in 3.3.6.
- With the shipped `sync.exclude` config, `list_indexable_files` raises `AttributeError` on 3.3.6. Local sync is broken and only the container works.
- Every change this session needed a separate 3.6.0 container run.

**Change.**
- Rebuild `.venv` from `pyproject.toml` against PyPI 3.6.0, with `uv sync` or `pip install -e .[dev]`.
- Commit `uv.lock` if uv is the tool.
- Remove the `skipif` on `test_indexable_config_exclude_patterns`.
- Ask the owner first whether the editable `~/Code/mempalace` checkout is still in use for upstream work.

**Proof.** `.venv/bin/python -m pytest -q` passes with no skips that depend on the mempalace version.

**Side note.** In the container, `tests/test_install_claude_code.py` fails 3 tests: `install_claude_code.sh` calls `python3`, which isn't on the container's PATH. That script only runs on the Mac host. Either skip those tests when `python3` is missing, or leave them, but don't read them as regressions.

### 6. Smarter incremental skip check

**Finding.**
- `SyncEngine._is_current` skips a wing only when HEAD matches the ledger, the last prune was `ok`, no files failed, and `git status --porcelain` is empty.
- All 9 repos have local changes, many of them untracked `.claude/settings.local.json` files that sync excludes anyway. So `mems sync` reruns every wing.

**Evidence.** A full incremental `mems sync` with nothing new to index took 9.5 s. Unchanged files are cheap, because `process_file` skips them by mtime.

**Verdict.** Not worth doing now. Sync is manual: `entrypoint.sh` runs it only on first boot, and no launchd job or hook calls it. It becomes worth doing if the owner approves Q3, a scheduled `mems sync` every 30 minutes.

**The fix, if wanted.** Pass the porcelain paths through the same filter as `list_indexable_files`. Count the wing as clean when none of the changed paths would be indexed. A deleted tracked file still counts as a change.
