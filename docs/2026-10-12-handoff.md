### 1. Remove the manual patch step

**Problem.** Search depends on a fix to mempalace that no release has. Today it is carried as `patches/mempalace-3.6.0-keep-drawer-text.patch`. The Dockerfile applies it. Locally, `scripts/apply_mempalace_patch.sh` must run after every `uv sync`, and `tests/test_search_dedup.py` fails if it didn't. The owner rejected this: setup must work with no step to remember.

**Proposed fix.** Fork mempalace to `themancalledzac/mempalace`. Put the fix on a branch based on the 3.6.0 tag (the same change as the patch). Depend on it in `pyproject.toml` with a pinned commit, `mempalace @ git+https://github.com/themancalledzac/mempalace@<sha>`. Then `uv sync` and `pip install .` in the Dockerfile both install the fixed version. Delete the patch file, the script, the Dockerfile `patch` step and apt package, the README note, and the "unpatched venv" test. Keep the tests that check each hit carries its own drawer's text.

## How the move works

- `docker-compose.yml` pins the project name `memory` and uses the external volume `memory_mempalace-data`. The live palace survives any folder rename. Only `docker volume rm memory_mempalace-data` deletes it. `scripts/setup.sh` creates the volume on a fresh machine.
- The Memory repo's own wing is still `memory`, mounted at `/repos/Memory`. `docker-compose.override.yml` maps `~/Code/mems:/repos/Memory:ro`. Never change the wing key or the container path. Drawers store `/repos/Memory/...` paths, and a new path would duplicate the wing.
- Gitignored files that must exist in `~/Code/mems`: `config/repos.json`, `docker-compose.override.yml`. Both are in place.
- Host config now points at `~/Code/mems`: the two hooks in `~/.claude/settings.json`, the `.venv/bin` PATH line in `~/.zshrc`, and the `memory` entry in `~/.config/mems/repos.json`.
