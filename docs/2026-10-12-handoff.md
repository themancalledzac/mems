### 1. Closet hits return the same chunk several times

Done. The cause was upstream: mempalace 3.6.0 `search_memories` rewrote every closet-boosted hit's `text` to its file's keyword-best chunk plus neighbours, so distinct drawers from one file came back identical. Upstream 3.9.0 and 3.10.0 still rewrite; they only drop the repeats and over-fetch.

Memory now carries `patches/mempalace-3.6.0-keep-drawer-text.patch`. Each hit keeps its own drawer's text, and closets only change ranking. Closet hits still get `drawer_index` (the hit's own chunk index) and `total_drawers`. The Dockerfile applies the patch after `pip install` and the build fails if it no longer applies. Locally, run `scripts/apply_mempalace_patch.sh` after every `uv sync`; `tests/test_search_dedup.py` fails on an unpatched `.venv`. The `_search_distinct` dedup and backfill (commit `fe3a678`) are removed from `src/tools.py`, and search latency is back to about 0.2 s.

The same fix is committed upstream-ready on `fix/closet-enrichment-keeps-drawer-text` in `~/Code/mempalace` (not pushed). The draft issue and PR text is `docs/upstream/2026-10-12-closet-enrichment-duplicates.md`.

Drop the patch, the script, the Dockerfile step and the README note once an upstream release keeps drawer text on closet hits.

### 6. Smarter incremental skip check

**Finding.**
- `SyncEngine._is_current` skips a wing only when HEAD matches the ledger, the last prune was `ok`, no files failed, and `git status --porcelain` is empty.
- All 9 repos have local changes, many of them untracked `.claude/settings.local.json` files that sync excludes anyway. So `mems sync` reruns every wing.

**Evidence.** A full incremental `mems sync` with nothing new to index took 9.5 s. Unchanged files are cheap, because `process_file` skips them by mtime.

**Verdict.** Not worth doing now. Sync is manual: `entrypoint.sh` runs it only on first boot, and no launchd job or hook calls it. It becomes worth doing if the owner approves Q3, a scheduled `mems sync` every 30 minutes.

**The fix, if wanted.** Pass the porcelain paths through the same filter as `list_indexable_files`. Count the wing as clean when none of the changed paths would be indexed. A deleted tracked file still counts as a change.
